## 一、问题

**现象**：用户说「当前项目各种乱七八糟文案都整理精简一下，学 dash」。盘点 716 条用户看得到的字：
同一样东西好几种叫法（云端副本 / 云端 / 远程；连不上 / 离线；读不出运行的提交 / 读不出版本；没推送 / 未推送），
悬停提示里大量「点击在分支图里打开」「点一下看详情」这类操作说明，健康检查和环境状态写成带成因的长句
（「可能是用没推送的本地代码部署的，或者云端副本还没同步到」），还有「BranchMap 每次探测到……就记一条」这种自述。

**原则**（照 Dash `docs/user-facing-copy.md`、`docs/design-system.md` §7）：
写状态名，不写句子；不解释成因、不写「请稍后重试 / 暂时 / 可以… / 会… / 不会…」；按钮和入口写动作或目的地名；
同一样东西只有一个名字；不知道就说不知道（「版本未知」，不编状态）；但不能把信息删空——数字、名字、时间留着。

**方案**：先定 BranchMap 的词表（写进 AGENTS.md「文案」一节，以后照它写），再逐文件替换。
给排查问题的人看的字（HTTP 状态码、字段名、git 命令）保留技术信息；控制台日志不在范围内。

**改动范围**：`web/app.js`、`web/views/{board,project,branches,members}.js`、`web/lib/{util,settings,addproject,code,flowui}.js`、
`server.mjs`、`lib/{auth,github,project,repo}.mjs`、`lib/engine/{health,pipeline}.mjs`、`lib/sources/{env,cloud}.mjs`。

## 三、实现记录

- **词表落在 AGENTS.md**：这是用户定的、别人写代码也要遵守的规则，按约定写进仓库，不只存在个人记忆里。
- **「读法」图例保留**：用户 2026-09-29 说看不懂分支图后专门要的读图说明，只压成三行，不删。
- **「移除项目」确认框留一句「不删除任何数据。」**：Dash 的例外——「分不清是删了还是看不到了」时留一句。
- **清理分支面板留一句「复制命令后在终端执行」**：删分支收不回来，而 BranchMap 自己不删，这句是做决定时要知道的。
- **探测失败的提示保留字段名**：「接口需返回提交号，如 {"commit": …}（也认 sha、gitSha、revision）」是给配置的人看的，删了就配不出来。
- **服务端报错统一成「X 无效 / X 不存在 / X 失败」**：它们会以提示条出现在页面上。
