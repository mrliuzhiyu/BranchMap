## 一、问题

**现象**：BranchMap 只有一份 README，没有给 agent 的指令文件、没有改动记录、没有待办。
用户定下的产品约定（只读、通用、设计规则、不做的功能）只存在一台机器的个人记忆里，
别的会话、别的机器、以后的同事都读不到；记忆里写着「待做」的四个功能，查代码其实都已做完——
没有任何地方记录完成情况。

**原则**：判断现状以代码为准，文档只是线索；团队规则写进仓库文件，不只存记忆；
一个事实只存一处；规则靠闸守，不靠自觉。

**方案**：照抄 `siltok_web` 已经跑了两个多月的那套（AGENTS.md 唯一真源 + `CLAUDE.md` 一行指针、
`docs/` 状态头与索引、`issues/` 四步、`TODOS.md`、`scripts/check-docs.mjs`），只删掉单仓用不上的两块：

- 五仓共同约定段与它的 sha256 校验——BranchMap 不属于那五个仓。
- Multica 任务台账——BranchMap 没有它，任务就记在 `issues/` 与 `TODOS.md`。

不选「只写一份 CLAUDE.md」：Siltok 已经验证过，两份指令文件并行维护必漂，而没有闸的文档没人回来改。
不搬 Siltok 的测试锁、门禁缓存、pre-push 钩子：BranchMap 没有自动化测试，也没有 CI，搬过来是空架子。
运维只写现状与步骤（`docs/DEPLOY.md`），不先写部署脚本——还没定在哪台机器上跑。

**改动范围**：

| 文件 | 改什么 |
|---|---|
| `AGENTS.md`、`CLAUDE.md` | 新增：工程指令 + 用户定下的产品约定与完成情况 |
| `docs/DOC_GOVERNANCE.md`、`docs/README.md`、`docs/DEPLOY.md` | 新增：治理规则、索引、运行与部署 |
| `issues/README.md`、`issues/TEMPLATE.md`、本文件 | 新增 |
| `TODOS.md` | 新增：落文档时发现的两处「停滞」阈值不一致、部署待办 |
| `scripts/check-docs.mjs`、`package.json` | 新增文档闸与 `npm run check:docs` |
| `README.md` | 代码结构补上漏写的四个模块，指向 AGENTS.md |
